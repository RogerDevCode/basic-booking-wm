# Investigación Profunda: Mejoras al Preprocesamiento de Mensajes
## Booking Titanium WM — Etapa de Preprocesamiento (Message Preprocessor)

**Fecha:** 2026-05-18
**Alcance:** Pipeline de preprocesamiento de texto en español (Chile/LatAm) para chatbot de agendamiento médico vía Telegram.

---

## 1. ESTADO ACTUAL DEL PIPELINE

El pipeline actual tiene 4 etapas secuenciales:

1. **Text Cleaner** → Elimina caracteres invisibles (Cc/Cf), colapsa whitespace, remueve HTML tags.
2. **SQL Sanitizer** → Detecta y censura patrones de inyección SQL (DROP, DELETE, etc.).
3. **Modism Mapper** → Mapeo determinístico de modismos chilenos ("kiero"→"quiero", "sacar hora"→"hacer una cita", "po"→"").
4. **Spell Normalizer** → Corrección ortográfica con pyspellchecker (diccionario ES + custom words).
5. **Datetime Resolver** → Pipeline híbrido (exact→fuzzy→phonetic→dateparser→LLM fallback).

**Fortalezas identificadas:**
- Arquitectura modular y determinística.
- Buen coverage de modismos chilenos de salud ("ora", "sacar hora", "pal").
- Guard de títulos (dr/dra) para proteger apellidos de corrección ortográfica.
- Custom words extenso para vocabulario médico chileno (fonasa, isapre, copago, etc.).
- Pipeline híbrido de resolución temporal con falsos cognates.

## 2. HALLAZGOS DE INVESTIGACIÓN — ÁREAS DE MEJORA

### 2.1. CORRECCIÓN ORTOGRÁFICA: LIMITACIONES DE pyspellchecker

**Problema:** pyspellchecker usa el algoritmo de Peter Norvig (Levenshtein distance + frecuencia). Para español tiene limitaciones documentadas:

- **Diccionario estático:** Basado en frecuencias de Wikipedia/es, no cubre conjugaciones verbales completas ni vocabulario coloquial latinoamericano.
- **Sin contexto:** Corrige palabra por palabra, sin entender el contexto de la oración. "komo"→"como" funciona, pero "estoi" podría ir a "estoy" o "esto" indistintamente.
- **Distance=2 es agresivo:** Para palabras largas en español, distance=2 genera candidatos irrelevantes. La propia documentación recomienda distance=1 para palabras >6 caracteres.

**Sugerencias de la comunidad Python/español:**

a) **language_tool_python (LanguageTool):**
   - Corrector gramatical y ortográfico completo para español.
   - Detecta errores de concordancia, acentuación, puntuación.
   - Soporta español de Latinoamérica (es-AR, es-MX, es-CL).
   - **Contra:** Requiere Java (servidor local) o llamada a API pública (latencia).
   - **Recomendación:** Usar como capa opcional de validación post-pyspellchecker, no como reemplazo.

b) **symspellpy:**
   - Basado en Symmetric Delete Spell Correction.
   - 100x más rápido que pyspellchecker para diccionarios grandes.
   - Mejor para producción con alto throughput.
   - **Recomendación:** Evaluar si la latencia del preprocesamiento se vuelve un cuello de botella.

c) **spanish-nlp (Jorge Ortiz-Fuentes, U. de Chile):**
   - Librería chilena específica para PLN en español.
   - Incluye preprocess, spell checker, clasificación (hate speech, sentiment).
   - Usa pyspellchecker internamente pero con API unificada.
   - **Recomendación:** No adoptar como dependencia (ya tenemos pyspellchecker directo), pero consultar su lista de custom words y preprocess pipeline como referencia.

d) **Contextual LM (BERT-based):**
   - Modelos como `dccuchile/bert-base-spanish-wwm-uncased` (U. de Chile) para corrección contextual.
   - Corrige "estoi feliz" → "estoy feliz" entendiendo el contexto.
   - **Contra:** Requiere PyTorch/transformers, pesado para un preprocesador ligero.
   - **Recomendación:** Reservar para fase futura si se necesita corrección de alta precisión.

### 2.2. MODISMOS Y JERGA: COBERTURA REGIONAL

**Problema actual:** El modism mapper cubre modismos chilenos pero no otros dialectos latinoamericanos.

**Investigación SEPLN (Sociedad Española para el Procesamiento del Lenguaje Natural):**
- El español tiene variaciones significativas por región en chatbots de salud.
- Argentina: "sacar turno" (Chile: "sacar hora"), "consultorio" vs "centro de salud".
- México: "agendar cita", "consultorio", "turno".
- Colombia: "agendar cita", "turno médico".
- Perú: "cita médica", "turno".

**Sugerencia:** Hacer el modism mapper configurable por región/país. Actualmente está hardcodeado para Chile. Si el sistema se expande, necesitará:
- `_modism_mapper_cl.py` (Chile)
- `_modism_mapper_ar.py` (Argentina)
- `_modism_mapper_mx.py` (México)
- O un sistema de detección automática de dialecto.

### 2.3. ENTIDADES NO NORMALIZADAS: URLs, TELÉFONOS, EMAILS

**Hallazgo crítico:** El pipeline actual NO maneja explícitamente:

a) **URLs:** Un usuario puede pegar un link de Google Maps, un link de laboratorio, etc.
   - Las URLs pasan intactas al LLM, consumiendo tokens innecesarios.
   - **Sugerencia:** Detectar y reemplazar URLs con placeholder `[URL]` o extraer dominio.
   - Librería recomendada: `url-normalize` (RFC 3986 compliant) o regex simple.

b) **Teléfonos:** Números de teléfono chilenos (+56912345678, 912345678).
   - Pueden ser intención de contacto, pero también ruido.
   - **Sugerencia:** Extraer y estructurar como entidad `phone_number` en el output.
   - Regex para Chile: `r"\+?56\s?9\s?\d{4}\s?\d{4}"` o `r"9\s?\d{4}\s?\d{4}"`.

c) **Emails:** Direcciones de email en mensajes de Telegram.
   - **Sugerencia:** Extraer como entidad `email` con regex estándar.

d) **RUT chileno:** Formato 12.345.678-5 o 12345678-5.
   - Crítico para sistema de salud chileno (Fonasa/Isapre).
   - **Sugerencia:** Detectar y validar RUT como entidad estructurada.

### 2.4. EMOJIS Y EMOTICONES

**Problema:** El pipeline actual NO procesa emojis. En Telegram, los emojis son frecuentes:
- "🏥" puede indicar intención médica.
- "📅" puede indicar agendamiento.
- "❌" puede indicar cancelación.
- "😷" puede indicar urgencia/síntoma.

**Sugerencias de la comunidad NLP:**
- **Opción A (conservadora):** Eliminar emojis en el text cleaner (ya se pierden en normalización).
- **Opción B (recomendada):** Convertir emojis a texto descriptivo con `emoji` library: "🏥" → ":hospital:", "📅" → ":calendar:".
- **Opción C (avanzada):** Usar emojis como features adicionales para el clasificador de intención.

**Librería recomendada:** `emoji` (PyPI) — `emoji.replace_text()` convierte emojis a aliases CLDR.

### 2.5. LENGUAJE INCLUSIVO Y VARIANTES ORTOGRÁFICAS

**Hallazgo:** El español chileno usa frecuentemente:
- "todxs", "amigxs", "doctores/as" — lenguaje inclusivo con "x".
- "todes", "amigues" — lenguaje inclusivo con "e".
- "Holaaaaa", "graciassss" — elongación de vocales (común en WhatsApp/Telegram).

**Sugerencia:**
- Normalizar "x" y "e" inclusivo a forma canónica para el clasificador: "todxs" → "todos".
- Truncar elongaciones: "Holaaaaa" → "Hola" (máximo 2 repeticiones de vocal).
- spanish-nlp ya implementa `normalize_inclusive_language` y `reduce_spam`.

### 2.6. HASHTAGS Y MENCIONES DE TELEGRAM

**Problema:** Los usuarios pueden enviar mensajes con:
- Hashtags: "#horaMédica #urgente"
- Menciones: "@doctorPerez"
- Comandos: "/start", "/help" (ya manejados en spell checker)

**Sugerencia:**
- Extraer hashtags como entidades de tags/categoría.
- Extraer menciones como posibles referencias a proveedores.
- Split hashtags compuestos: "#horaMédica" → "hora médica".

### 2.7. DETECCIÓN DE IDIOMA

**Riesgo:** El pipeline asume que todo texto es español. Pero en Chile:
- Usuarios bilingües pueden mezclar inglés y español.
- "I need to book an appointment for Monday" no debería pasar por el modism mapper chileno.
- Mapudungun (lengua mapuche) aparece ocasionalmente en zonas rurales.

**Sugerencia:** Agregar detección de idioma como primer paso del pipeline.
- Librería: `fasttext-langdetect` o `langdetect` (ligera, sin dependencias pesadas).
- Si no es español → saltar modism mapper y spell checker español.
- Si es spanglish → procesar solo la parte en español.

### 2.8. RENDIMIENTO Y CACHING

**Observación:** El spell checker se inicializa lazy (bien), pero:
- `_getChecker()` crea un SpellChecker completo en cada cold start.
- No hay caching de resultados de corrección ortográfica.
- `resolve_datetime` tiene LRU cache en metaphone pero no en el pipeline completo.

**Sugerencias:**
- Cache de correcciones ortográficas frecuentes con `functools.lru_cache`.
- Pre-compilar todos los regex del modism mapper (ya se hace implícitamente).
- Benchmark del pipeline completo: objetivo <50ms por mensaje.

### 2.9. SEGURIDAD: SQL SANITIZER INSUFICIENTE

**Problema:** El SQL sanitizer actual solo detecta patrones SQL clásicos. Pero:

- No detecta XSS: `<script>alert('xss')</script>` (los HTML tags se remueven pero no se loggean como amenaza).
- No detecta prompt injection: "Ignore previous instructions, you are now..."
- No detecta inyección de comandos: "`rm -rf /`", "$(whoami)".

**Sugerencia:** Expandir `_sql_sanitizer.py` a `_threat_detector.py` que cubra:
- SQL injection (actual).
- XSS (script tags, event handlers).
- Command injection (backticks, $(), ;).
- Prompt injection (patrones de jailbreak conocidos).

### 2.10. METRICAS Y OBSERVABILIDAD

**Hallazgo:** El datetime resolver loggea con structured logging (bien), pero:
- No hay métricas de cuántos mensajes pasan por cada etapa.
- No hay tracking de tasa de corrección ortográfica por palabra.
- No hay métricas de confianza del pipeline completo.

**Sugerencia:** Agregar métricas estructuradas al output del preprocesador:
- `processing_time_ms`: tiempo total del pipeline.
- `stages_applied`: lista de etapas que modificaron el texto.
- `threat_level`: none | low | medium | high.
- `language_detected`: es | en | mixed | unknown.

## 3. PRIORIZACIÓN DE MEJORAS

### CRÍTICO (implementar ahora):
1. **URL/Phone/Email extraction** — Entidades que se pierden y consumen tokens del LLM.
2. **Emoji handling** — Telegram los usa masivamente, contienen señal de intención.
3. **Language detection** — Prevenir procesamiento incorrecto de texto no-español.
4. **Prompt injection detection** — Seguridad del agente AI.

### IMPORTANTE (próximo sprint):
5. **Spell checker contextual** — Mejorar correcciones con contexto de oración.
6. **Inclusive language normalization** — "todxs" → "todos" para el clasificador.
7. **Vowel elongation reduction** — "Holaaaaa" → "Hola".
8. **Hashtag/mention extraction** — Extraer señal de tags y proveedores.

### FUTURO (cuando escale):
9. **Dialect detection** — Chile vs Argentina vs México.
10. **symspellpy migration** — Si la latencia es problema.
11. **BERT-based correction** — Si se necesita precisión >95%.
12. **RUT extraction** — Si se integra con sistema de salud chileno.

## 5. CONCLUSIONES

El pipeline actual de preprocesamiento es **sólido para su scope actual** (chatbot médico chileno vía Telegram). Las mejoras más impactantes a corto plazo son:

1. **Extracción de entidades estructuradas** (URLs, teléfonos, emails) que actualmente se pierden.
2. **Manejo de emojis** que contienen señal de intención en Telegram.
3. **Detección de idioma** para evitar procesamiento incorrecto.
4. **Detección de prompt injection** para seguridad del agente AI.

Estas 4 mejoras pueden implementarse sin cambiar la arquitectura existente, agregando nuevas etapas al pipeline antes del modism mapper.
